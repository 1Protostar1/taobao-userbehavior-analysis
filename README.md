# 淘宝 UserBehavior 用户行为分析

对 1 亿行淘宝用户行为日志做全量分析。数据是单文件 CSV（3.42GB，100,150,807 行），
覆盖 987,994 用户、9 天（2017-11-25 ~ 2017-12-03）的浏览 / 加购 / 收藏 / 购买行为，
时间戳按北京时间（UTC+8）解释。

pandas 全量读入大概要 30GB 内存，单机跑不动，所以核心计算都走 DuckDB，直接对 CSV 执行 SQL。

## 结论速览

| 指标 | 数值 | 口径 |
|---|---|---|
| 浏览 → 成交转化率 | 39.9% | UV 口径（9 天，含顺序约束） |
| 浏览 → 成交转化率 | 1.36% | Session 口径（30 分钟会话内闭环） |
| 复购率 | 55.1% | 购买天数 ≥ 2 天 |
| 次日留存率 | 65.4% | 首日活跃 cohort，剔除 11-25 存量混合 cohort |
| 核心用户购买贡献 | 6.9% 用户 / 29.8% 购买 | KMeans(K=6) 与 RFM 交叉验证一致（Cramér's V=0.29） |

几个值得说的发现：

- 漏斗最陡的一段是「加购/收藏 → 购买」——Session 口径下意向会话只有 7.0% 当次成交；
  丢人最多的一段是「浏览 → 加购/收藏」——80.6% 的浏览会话没有产生任何意向行为。
- 加购用户最终购买概率 71.9%、收藏 71.1%、纯浏览 53.7%（口径：用户是否买过任何东西，非单品归因）。
- 留存曲线会"翘尾"，逐个 cohort 排查后确认是周末日历效应，不是粘性变好。
- 周末 DAU 更高，但转化率反而比工作日低 1.58pp——周末增量流量以低意向用户为主。

## 数据上踩过的两个坑

1. 文件按 user_id 的**字符串字典序**排序，不是数值序。实测前 300 万行的用户顺序是
   `1 → 100 → 1000 → 1000001 → …`，所以 `read_csv(nrows=…)` 取到的是 ID 字典序最靠前的那批用户，
   系统性非随机。和分层随机抽样对照，行为结构差异 0.5%–6%，"看起来没偏"只是运气。
   完整论证见 `reports/data_quality_report.md`。
2. 有 55,576 行（0.055%）窗口外脏时间戳，最早到 1902 年、最晚到 2037 年；另有 2017-11-24
   全天 40,231 行采集爬坡数据。已在中间层按 `config.WINDOW_SQL` 统一剔除，原始文件不动。

## 关键口径

| 主题 | 本项目口径 | 为什么 |
|---|---|---|
| 时间戳 | 按北京时间（UTC+8）解释 | 淘宝站内日志，小时峰值应落在北京时间晚间 |
| 会话 session | 同用户相邻行为间隔 > 30 分钟切分 | 15 分钟会切碎、60 分钟会粘连；做了三档敏感性对照 |
| 漏斗结构 | `pv → (cart \| fav) → buy` | 加购与收藏是并列分支，串成先后关系会低估下游转化 |
| 漏斗口径 | UV 口径 + Session 口径双给 | UV 看整体经营效率，Session 看单次访问效率 |
| 漏斗顺序 | 要求 浏览 → 加购/收藏 → 购买 顺序正确 | "出现过"不等于"走过了这条链路" |
| RFM 的 F | 购买天数 | 比购买次数抗单次多笔与刷单 |
| RFM 的 M | 购买的不同商品件数（代理指标） | 数据无金额字段，无法衡量真实 GMV |
| RFM 打分 | 先 rank 再 qcut 五分位 | 均值 0/1 二分类丢区分度且受极端值影响 |
| 采样 | 结论用全量；探索用 user_id 哈希分层 10% | 文件按 user_id 排序，取前 N 行 = 系统性偏差 |

## 已知局限

9 天窗口（R 被压缩到 0–8 天、留存只能看短期）、无金额字段（M 为代理指标）、无用户画像、
无曝光数据、少量疑似爬虫流量。改进方向见报告第六章与 `reports/data_quality_report.md`。
